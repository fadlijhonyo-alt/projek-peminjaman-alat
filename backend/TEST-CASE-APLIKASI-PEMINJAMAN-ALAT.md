# Test Case Aplikasi Peminjaman Alat

## Ruang Lingkup dan Data Acuan

Dokumen ini mencakup alur aplikasi web dari login sampai pengembalian alat untuk Admin, Petugas, dan Peminjam. Bagian API dicantumkan terpisah karena aplikasi juga menyediakan endpoint Sanctum.

| Data | Nilai acuan |
|---|---|
| Akun Admin seed | `admin@gmail.com` / `password123` |
| Akun Petugas seed | `petugas@gmail.com` / `password123` |
| Akun Peminjam seed | `rian@gmail.com` / `password123`, `siti@gmail.com` / `password123` |
| Contoh alat seed | Router Mikrotik RB941-2nD (stok 15), Kamera DSLR Canon EOS 3000D (stok 5), Mini PC Intel NUC 11 (stok 8) |
| Contoh kategori seed | Jaringan & Konektivitas, Multimedia & Audio Visual, Perangkat Pemrosesan |
| Tanggal uji | `T` = tanggal pengujian; `T+N` = N hari setelah tanggal pengujian; `T-N` = N hari sebelumnya |
| Kondisi awal | Database sudah dimigrasikan dan diisi seeder; setiap skenario yang mengubah data dijalankan dengan data bersih atau data uji baru |

**Catatan:** Form akun menggunakan `Nama Lengkap`, `Email`, `Password`, `Role`, serta kolom opsional `No. HP` dan foto profil. Tidak ada kolom `Username`; kasus duplikasi akun menguji email yang unik. Akun contoh di atas adalah data seeder, bukan kredensial produksi.

**Pengisian hasil:** Kolom Actual Result dan Status sengaja ditandai belum diuji. Isi hasil aktual setelah eksekusi manual/otomatis; jangan menganggap kasus PASS sebelum diverifikasi.

## Temuan Risiko untuk Diperhatikan Saat Eksekusi

1. Endpoint login API membuat `ValidationException` kredensial salah tanpa melemparkannya. Kasus `API-AUTH-003` perlu memastikan implementasi nyata memberi respons autentikasi gagal, bukan meneruskan proses dengan user kosong.
2. Handler persetujuan pada web Petugas mengurangi stok setelah mengubah status tanpa validasi eksplisit bahwa status awal masih `diajukan`. `PET-003` adalah regresi penting untuk mendeteksi pengurangan stok berulang melalui request ulang.
3. Validasi tanggal berbeda antar kanal: form web Peminjam menerima tanggal kembali setelah hari ini, sedangkan request API memakai `after_or_equal:today`. Jalankan uji batas tanggal hari ini secara terpisah pada web dan API.
4. Pengembalian via web menetapkan status pinjaman `dikembalikan`; endpoint API menetapkan `telat` untuk pengembalian yang melewati tanggal rencana. Uji hasil tiap kanal dan sepakati status bisnis yang diharapkan.
5. Beberapa route API tersedia khusus untuk role tertentu; uji ulang batas akses untuk setiap kombinasi role, termasuk operasi update/delete, sebelum rilis.
